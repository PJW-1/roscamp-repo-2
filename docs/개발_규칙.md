# 개발 규칙

## 빌드

저장소를 `~/gg_ws/src/roscamp-repo-2`에 받은 뒤 장치에 필요한 패키지만 빌드합니다.

```bash
cd ~/gg_ws && source /opt/ros/jazzy/setup.bash
colcon build                                                                   # 관제 PC
colcon build --packages-up-to pinky_fsm pinky_dock pinky_nav_config iponic_bringup  # 핑키 Pi
colcon build --packages-up-to arm_control arm_vision iponic_bringup                 # 팔 PC
source install/setup.bash
```

핑키 Pi에는 제조사 패키지 `pinky_pro`도 있어야 합니다(`iponic.repos`에 고정한 커밋).

## 실행

도메인 6은 로봇 네트워크입니다. 시험할 때는 반드시 다른 도메인과 `LOCALHOST`로 띄웁니다.

```bash
export ROS_DOMAIN_ID=43 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
ros2 launch iponic_bringup pc.launch.py use_fake:=true scenario:=basic_orders result_dir:=/tmp/run1
```

ROS 없이 관제 로직만 시험할 때(저장소 폴더에서):

```bash
cd ~/gg_ws/src/roscamp-repo-2
pip install pytest pyyaml
PYTHONPATH=pc/fleet_core python -m pytest pc/fleet_core/test -q
```

## 규칙

- 브랜치는 `feat/…` `fix/…` `docs/…`, 커밋은 Conventional Commits.
- 인터페이스 이름·타입·QoS는 `interfaces/fleet_interfaces/contract.yaml`이 원본입니다.
- Python 패키지 `setup.py`에는 `tests_require=['pytest']`를 넣습니다. 없으면 colcon이 시험을 한 건도 돌리지 않습니다.

## 이름 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 패키지 | snake_case, 앞말은 역할 | `fleet_core`, `pinky_fsm` |
| 실행 파일 | 노드 이름 + `_node` | `fleet_manager_node` |
| 로봇별 노드 | 이름은 같게, namespace로 구분 | `/pinky1/pinky_fsm` |
| 토픽·서비스·액션 | `/{주인}/{무엇}` | `/fleet/zones`, `/pinky2/move_to` |
| 로봇 ID | 소문자 + 번호 | `pinky1`, `arm3` |
| 지점·구역 ID | 데이터에만 쓰고 ROS 이름에 넣지 않음 | `P-3`, `WORK` |
| 타입 | PascalCase, 목록은 `~Array` | `ZoneStateArray` |
| 상수·이벤트 코드 | UPPER_SNAKE | `STATE_MOVING`, `GOAL_RETRY` |
| 파라미터 | snake_case + 단위 | `release_distance_m` |
| launch | `{장치}.launch.py` | `pinky.launch.py` |
| 브랜치 | `feat/` `fix/` `docs/` | `feat/pinky-fsm-path` |
