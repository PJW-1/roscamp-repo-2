# 저장소 구조와 이름 (제안, 2026-11-06)

구역 잠금 + FollowPath 방식을 기준으로 폴더와 시스템 전체의 이름을 모았습니다. 팀 합의 전 제안입니다. 핑키 쪽 이름은 Drive `핑키_제어파트_전달사항_2026-11-06` 2절에 먼저 정리돼 있고, 이 문서는 그것을 전체로 넓힌 것입니다. "예정"은 Drive `FMS_개선_지시서_2026-11-06`의 번호이고 아직 코드에 없습니다.

## 1. 장치별로 누가 무엇을 내나

위가 아래를 부르고 아래는 상태와 결과만 올립니다. 핑키는 central, 팔, 레인 그래프를 모르고, 선은 `MoveTo.path`로 받습니다(예정 7번).

| 장치 | 패키지 | 노드 | 내는 이름 | 부르는 것 |
|---|---|---|---|---|
| 관제 PC | `central` (비어 있음) | 미정 | `/central/orders`, `/central/events`, srv `/central/submit_order` `/central/set_run_mode` `/central/report_order` | srv `/fleet/confirm_clear` |
| 관제 PC | `fleet_core` + `fleet_manager` | `fleet_manager` | `/fleet/robots` `/fleet/assignments` `/fleet/zones` `/fleet/heartbeat` `/central/events`, srv `/fleet/confirm_clear` | 액션 `/{pinky}/move_to` `/{pinky}/dock` `/workcell/fill_basket` `/arm3/swap_basket`, srv `/central/report_order` |
| 핑키 Pi ×3 | `pinky_fsm` `pinky_dock` `pinky_nav_config`, 제조사 `pinky_bringup` | `/{pinky}/pinky_fsm`(제안), Nav2 | `/{pinky}/state`, 액션 서버 `/{pinky}/move_to` `/{pinky}/dock` | 안에서 `/{pinky}/follow_path` 또는 `/{pinky}/navigate_to_pose` |

## 3. 이름 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 패키지 | snake_case, 프로젝트 접두어 없음. 앞말은 역할(`fleet_`, `pinky_`, `arm_`, `fake_`). 제조사 이름과 겹치지 않게 | `fleet_core`, `pinky_fsm` |
| 실행 파일과 노드 | 실행 파일 = 노드 이름 + `_node` | `fleet_manager_node` → `fleet_manager` |
| 로봇별 노드 | 이름은 같게, namespace로 구분, 같은 도메인 | `/pinky1/pinky_fsm` |
| 토픽·서비스·액션 | `/{주인}/{무엇}`, snake_case. 주인 = `central`, `fleet`, `{pinky}`, `{arm}`, `workcell` | `/fleet/zones`, `/pinky2/move_to` |
| 로봇 ID | 소문자 + 번호, ROS 이름에 들어감 | `pinky1`, `arm3` |
| 지점·구역·스테이션 ID | 데이터에만. ROS 이름에 넣지 않음(하이픈 불가) | `W`, `P-3`, `AVENUE`, `WORK` |
| 타입 | PascalCase 명사, 목록은 `~Array` | `ZoneStateArray` |
| 값 상수 | 값은 UPPER_SNAKE, 상수 이름은 `분류_값` | `STATE_MOVING`, `FAULT_COMM_LOST` |
| 이벤트 코드 | UPPER_SNAKE, `대상_무엇` | `GOAL_RETRY` |
| 파라미터 | snake_case + 단위 접미사 `_m` `_s` `_hz` | `release_distance_m` |
| TF 프레임 | 공용 `map`, 로봇 프레임은 `{pinky}/` 접두어(실물 미시험) | `pinky1/odom` |
| launch | `{장치}.launch.py` | `pinky.launch.py` |
| 지도·설정 | `{무엇}_map.yaml`, `{무엇}_params.yaml` | `lane_map.yaml` |
| 낱말 | 지점(waypoint), 레인, 구역(zone), 스테이션, 도크, 대기 지점(parking). "노드"는 ROS 노드에만 | |
| 브랜치·커밋 | `main` 하나, `feat/…` `fix/…` `docs/…`, Conventional Commits | `feat/pinky-fsm-path` |
| 장치 정체성 | 저장소 밖 `~/.iponic_env`의 `ROBOT_NS`, `ROS_DOMAIN_ID` | `ROBOT_NS=pinky2` |

## 5. 값 이름

| 필드 | 값 |
|---|---|
| 핑키 상태 | `IDLE` `MOVING` `WAITING` `DOCKING` `DOCKED` `ERROR` (+ `BLOCKED` 예정 4번) |
| 임무 단계 | `IDLE` `PARKED` `TO_PARK` `TO_WORK` `TO_OUTBOUND` `DOCKING` `AT_STATION` |
| fault | `NONE` `ERROR` `COMM_LOST` `RECOVERING` `OUT_OF_SERVICE` |
| task_type | `TO_WORK` `FILL` `TO_OUTBOUND` `SWAP` `WAIT` |
| 주문 상태 | `PENDING` `BOUND` `FILLING` `TO_OUTBOUND` `SWAPPING` `SHIPPED` `PARTIAL` `HELD` |
| 바구니 | `EMPTY` `FULL` `NONE` |
| 운영 모드 | `RUN` `PAUSE` `STOP` |
| 이동 실패 이유 | `NAV_ABORTED` `CANCELED` `TIMEOUT` |
| 예정 이벤트 | `INPUT_REJECTED`(1번) `GOAL_STALLED`(2번) `LANE_BLOCKED` `LANE_CLEARED`(4번) `ROBOT_ISOLATED`(5.5번) `ROBOT_REINSTATED`(6번) |

이름이 붙은 값만 적었습니다. `fsm_state`는 첫 보고 전, `task_type`은 로봇이 빠졌을 때 빈 문자열입니다. `reason`은 자유 문자열이고, 서버가 이유를 비운 채 abort하면 FMS가 `ABORTED`로 채웁니다. 지금 이벤트 코드 전체는 공통설계 0절에 있습니다.

## 6. 정리할 이름

| 이름 | 문제 | 제안 | 이 브랜치 |
|---|---|---|---|
| `.github/CODEOWNERS.txt` | GitHub는 확장자 없는 `CODEOWNERS`만 읽음 | 이름 바꾸기 | 바꿈 |
| Gazebo 패키지 | `pinky_gz_sim`은 제조사가 씀 | `fleet_gz_sim` | 만듦 |
| `RobotState` / `RobotStatus` | 한 글자 차이, 방향 반대 | `RobotState` → `PinkyState`(`ArmState`와 짝) | 안 함. 계약 변경이고 4·7번 작업과 겹침 |
| 같은 값이 여러 목록에 | `TO_OUTBOUND`가 세 곳, `DOCKING`·`IDLE`·`ERROR`·`NONE`이 두 곳 | 화면·로그에 `필드=값`으로 | 안 함 |
| `/central/events` | 발행자가 둘, "접두어 = 주인"의 예외 | 유지하고 계약 주석에 적기 | 안 함 |
| `/{pinky}/navigate_to_pose` | path 모드에서는 `follow_path`가 주 | 핑키 내부라 계약에서 빼기 | 안 함. 전달사항 7절 질문 11 |
| `/workcell/fill_basket` / `/arm3/swap_basket` | 스테이션 이름과 팔 이름이 섞임 | 팔 쪽 구조가 정해질 때까지 유지 | 안 함 |
| `iponic` | `iponic_bringup` `iponic.repos` `~/.iponic_env` `/tmp/iponic_result` | 프로젝트 이름이 정해지면 한꺼번에 | 안 함 |
